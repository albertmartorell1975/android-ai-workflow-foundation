# Module Architecture Specialist

This skill ensures that the project's multi-module structure remains healthy and strictly follows Clean Architecture boundaries.

> [!IMPORTANT]
> **Reference Values (SDKs)**: SDK Versions (`minSdk`, `targetSdk`, `compileSdk`) MUST be dynamically resolved. The Android Studio New Project Wizard typically defines the `minSdk` and `targetSdk`/`compileSdk` inside the `:app/build.gradle.kts` file upon project creation. Agents MUST check `libs.versions.toml` first, and if not present there, strictly extract the exact values generated by the wizard in the `:app` module.
> **Reference Values (Java)**: **Java 17 (JDK 17) is the MANDATORY minimum baseline** for modern tooling (AGP 8.x+) and Kotlin 2.0 (K2) performance. However, if the project is already using a newer version (e.g., Java 21) in the `:app` module or `libs.versions.toml`, agents MUST detect and apply that newer version to all new modules to ensure consistency.

## Modularization Strategy (Current vs. Future)

The agent MUST understand the project's evolution path regarding modularization:
*   **Current State (Layer-Based PoC)**: The project uses a horizontal Layer-Based architecture (`:app`, `:data`, `:domain`, `:usecases`). This is a didactic choice to strictly enforce Clean Architecture boundaries and is the default behavior for this skill.
*   **Future Scale (Feature-Based)**: For scalability, the project can transition to a vertical Feature-Based architecture.
> [!NOTE]
> For instructions on how to migrate to or build Feature Modules (e.g., `:feature:login`, `:core:network`), agents MUST read [`references/feature-modularization-strategy.md`](references/feature-modularization-strategy.md).

## Golden Rules (MANDATORY for Layer-Based)

1. **The Trinity of Purity**: `:domain` and `:usecases` MUST be **pure Kotlin/JVM** modules (No `android {}` block allowed). The `:data` module MUST be an Android Library (`com.android.library`) to support Android-specific data infrastructure like Room or DataStore, but it MUST NOT contain any UI dependencies (like Compose or Views). JSR-330 (`javax.inject`) is the permitted dependency for framework-agnostic Dependency Injection across layers.
2. **Implementation Strategy**: Data infrastructure and implementations (e.g., Room databases, DAOs, Retrofit services, Repository implementations) MUST reside in the `:data` module. The `:app` module is strictly reserved for the UI layer (Compose), framework entry points (Activity, Application), and Dependency Injection wiring.
3. **No Hardcoded Strings**: All plugins applied via `alias(libs.plugins.[name])`.
4. **Local Ignoring Mandate (STRICT)**: Every module MUST have its own `.gitignore` file to ensure build artifacts are not tracked by Git.

## Individual Module Blueprints

### 1. The `:domain` Module (Pure Kotlin)
```kotlin
plugins {
    alias(libs.plugins.kotlin.jvm)
}

java {
    sourceCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
    targetCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
}

kotlin {
    compilerOptions { jvmTarget.set(org.jetbrains.kotlin.gradle.dsl.JvmTarget.JVM_[JAVA_VERSION]) }
}

dependencies {
    // JSR-330 for framework-agnostic DI
    implementation(libs.javax.inject)
    // Other pure Kotlin libraries like Coroutines.
}
```

### 2. The `:data` Module (Data Infrastructure & Repositories)
**Type**: Android Library (No UI)
```kotlin
plugins {
    alias(libs.plugins.android.library)
    alias(libs.plugins.kotlin.android)
    // Add KSP if using Room: alias(libs.plugins.ksp)
}

android {
    namespace = "[PACKAGE_NAME].data"
    compileSdk = [COMPILE_SDK]

    defaultConfig {
        minSdk = [MIN_SDK]
        testInstrumentationRunner = "androidx.test.runner.AndroidJUnitRunner"
    }

    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
        targetCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
    }
}

kotlin {
    compilerOptions { jvmTarget.set(org.jetbrains.kotlin.gradle.dsl.JvmTarget.JVM_[JAVA_VERSION]) }
}

dependencies {
    implementation(project(":domain"))
    // Room, Retrofit, DataStore go here
    implementation(libs.javax.inject)
}
```

### 3. The `:usecases` Module (Pure Kotlin Orchestrator)
```kotlin
plugins {
    alias(libs.plugins.kotlin.jvm)
}

java {
    sourceCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
    targetCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
}

kotlin {
    compilerOptions { jvmTarget.set(org.jetbrains.kotlin.gradle.dsl.JvmTarget.JVM_[JAVA_VERSION]) }
}

dependencies {
    implementation(project(":domain"))
    // JSR-330 for framework-agnostic DI (if needed here)
    implementation(libs.javax.inject)
}
```

### 4. The `:app` Module (Android Framework & UI)
```kotlin
plugins {
    alias(libs.plugins.android.application)
    alias(libs.plugins.kotlin.compose)
    // add others potential plugins: alias(libs.plugins.hilt)
}

android {
    namespace = "[PACKAGE_NAME]"
    compileSdk = [COMPILE_SDK]

    defaultConfig {
        applicationId = "[PACKAGE_NAME]"
        minSdk = [MIN_SDK]
        targetSdk = [TARGET_SDK]
        versionCode = 1
        versionName = "1.0"
        testInstrumentationRunner = "androidx.test.runner.AndroidJUnitRunner"
    }

    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
        targetCompatibility = JavaVersion.VERSION_[JAVA_VERSION]
    }
}

dependencies {
    implementation(project(":domain"))
    implementation(project(":data"))
    implementation(project(":usecases"))

    // Android, Compose, and DI Libraries
    implementation(platform(libs.androidx.compose.bom))
    // ...
}
```

### 5. Standard Module `.gitignore`
**Responsibility**: Prevent build binaris from being tracked.
```text
/build
```

## Package Structure Example

To satisfy the Clean Architecture boundaries, contracts live in `:domain`, while their implementations live in `:data`. Business logic orchestration lives in `:usecases`. UI and DI wiring remain in `:app`.

```text
:domain
└── src/main/java/com/martorell/albert/basketcoach/domain
    ├── model/                       // Pure Kotlin business models
    │   └── BasketMatch.kt
    └── repository/
        └── BasketRepository.kt      // The INTERFACE (Contract)

:data
└── src/main/java/com/martorell/albert/basketcoach/data
    ├── network
    │   ├── ApiService.kt            // Retrofit interface
    │   └── model/                   // Network DTOs
    ├── database
    │   ├── AppDatabase.kt           // Room Database abstract class
    │   ├── dao/                     // Room DAOs
    │   └── entity/                  // Room Entities
    └── repository
        └── BasketRepositoryImpl.kt  // IMPLEMENTS interface from :domain (Mappers go here)

:usecases
└── src/main/java/com/martorell/albert/basketcoach/usecases
    ├── GetBasketMatchesUseCase.kt   // Orchestrates business logic using repositories
    └── ToggleMatchFavoriteUseCase.kt

:app
└── src/main/java/com/martorell/albert/basketcoach
    ├── di
    │   ├── NetworkModule.kt         // Hilt Module (provides Retrofit, Room DB using Context)
    │   └── RepositoryModule.kt      // Hilt Module to @Binds implementations
    ├── ui
    │   └── main/                    // Main screen (Compose + ViewModel)
    └── MainActivity.kt
```

## Operational Workflow

1. **Audit**: Verify SDK/Java versions in `libs.versions.toml`. Ensure `javax.inject:javax.inject` is defined in the catalog for pure Kotlin DI.
2. **Creation**: Apply the specific Blueprint to the new module's `build.gradle.kts` and create the local `.gitignore`.
3. **Registration**: Add `include(":module_name")` to `settings.gradle.kts`.
4. **Wiring**: Connect dependencies according to the blueprints above.
5. **Sync**: Mandatory Gradle Sync via `compiler` skill.
